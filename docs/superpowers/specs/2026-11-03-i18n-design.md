# 多語言 (i18n) 架構設計

日期：2026-11-03
狀態：已確認（2026-11-03）

## 1. 目的與緣由

目前所有介面文字、按鈕、提示、通知與曲目內容都直接寫死在 Dart 程式碼與原生小工具中（約 400 餘處繁中字串）。
受眾除台灣外，主要是香港、馬來西亞、新加坡，因此要支援 **繁體中文、簡體中文、英文** 三種語言，
並把架構整理成「文字與程式碼解耦」，之後新增語言或修改文案只需改翻譯檔，不必動畫面程式碼。

## 2. 目標 / 非目標 / 反目標

**目標**
- 三種語言：繁體中文（主語言，即現有文字）、簡體中文、英文。
- 所有使用者看得到的文字都走翻譯層：畫面、按鈕、tooltip、Toast、對話框、通知、桌面小工具、背景播放通知。
- 曲名、演出者、分類標籤、佛號與迴向文也提供三語版本（使用者已確認英文版要有英文翻譯）。
- 依手機語言自動選擇，且 App 內可手動切換語言。
- 經典模式與現代模式都要翻譯。

**非目標**
- 從右到左 (RTL) 語言支援、方向性排版改寫（三個語言都不需要）。
- 跨語言搜尋（例如輸入拼音找到繁中曲名）。
- 商店上架文案、隱私權政策 HTML 的翻譯。
- 改音檔檔名或音檔內嵌 metadata。

**反目標（做了也算失敗）**
- 切換語言後，篩選、搜尋、目標、計數、紀錄等功能行為改變或壞掉。
- 英文較長導致按鈕或排版溢位（尤其自動計數那一排小按鈕、底部分頁列）。
- 翻譯檔之間 key 不一致，導致某語言默默顯示成別的語言。
- 現有繁中使用者升級後看到的文字或曲名和現在不同。

## 3. 語言與地區對應

| 語言 | 代碼 | 主要受眾 | 系統語言符合以下即自動套用 |
|---|---|---|---|
| 繁體中文 | `zh_Hant` | 台灣、香港、澳門 | `zh` + script `Hant`，或地區 `TW` / `HK` / `MO` |
| 簡體中文 | `zh_Hans` | 馬來西亞、新加坡、中國 | `zh` + script `Hans`，或地區 `CN` / `SG` / `MY`，或只有 `zh` 無其他資訊 |
| 英文 | `en` | 其他 | 其他所有語言 |

- 解析規則為一支純函式 `resolveAppLocale(deviceLocales, preference)`，依手機語言偏好清單**依序**找第一個符合的語言；
  清單中都沒有中文或英文時回退英文。
- App 內語言設定：`跟隨系統`（預設）／`繁體中文`／`简体中文`／`English`。
  選項名稱一律以該語言本身顯示，「跟隨系統」依目前語言顯示。
  存於 `StorageService` 新 key `pref_locale`（值：`system` / `zh_Hant` / `zh_Hans` / `en`）。
- 設定入口：現代模式側邊選單（Drawer）新增「語言」項目；經典模式設定頁新增「語言」區塊。
- 監聽系統語言變更（`didChangeLocales`），設定為跟隨系統時即時切換。

## 4. 架構

### 4.1 介面文字：Flutter gen-l10n (ARB)

```
l10n.yaml
lib/l10n/
  app_zh.arb        ← 範本 (template)，內容為繁體中文
  app_zh_Hant.arb   ← 只有 @@locale，繼承 app_zh
  app_zh_Hans.arb   ← 完整簡體翻譯
  app_en.arb        ← 完整英文翻譯
  l10n_extensions.dart   ← `context.l10n` 擴充
  locale_resolver.dart   ← resolveAppLocale 與 AppLanguage 列舉
tools/check_arb_parity.sh ← 檢查三份完整翻譯檔 key 與 placeholder 一致
```

- `l10n.yaml`：`arb-dir: lib/l10n`、`template-arb-file: app_zh.arb`、`nullable-getter: false`，
  產出 `AppLocalizations`。少翻一條 key 或打錯 key 會編譯失敗。
- 範本用繁中（偏離 Flutter 慣用的英文範本）：現有文字全是繁中，日後新增文案也是先寫繁中。
  gen-l10n 規定有 `zh_Hant` / `zh_Hans` 時必須存在語言層 `app_zh.arb`，故範本即為 `app_zh.arb`。
- 每條 key 需有 `@key.description`（給翻譯者看的上下文），帶數字者宣告型別化 placeholder。
- 含數字的句子用整句 ICU 樣板，不拼接字串；英文單複數用 `{count, plural, ...}`。
- 命名規則：`<畫面或功能>_<用途>`，lowerCamel，例如 `autoStopSheetTitle`、`counterResetConfirmBody`。
  共用字（取消、設定、確認）用 `common*` 前綴。
- `MaterialApp` 設 `localizationsDelegates: AppLocalizations.localizationsDelegates`、
  `supportedLocales: AppLocalizations.supportedLocales`、`locale:` 由 ViewModel 提供的已解析語言。
  Material 內建元件（日期選擇器、時間選擇器）會跟著語言變。
- `MaterialApp.title` 改用 `onGenerateTitle`。

### 4.2 曲目與經文內容：內容目錄 (Content Catalog)

曲名、演出者、專輯、佛號、迴向文屬於「內容資料」而非介面字串，量大且結構化，不放 ARB。

```
lib/core/content/
  chant_content.dart          ← 抽象介面 ChantContent
  chant_content_zh_hant.dart  ← 現有繁中內容（自 chant_songs.dart 搬出）
  chant_content_zh_hans.dart
  chant_content_en.dart
```

- `ChantContent` 提供：`songTitle(id)`、`songArtist(id)`、`defaultArtist`、`defaultAlbum`、`huiXiangItems`。
- `ChantSong` 只保留**與語言無關的資料**：id、音檔路徑、節拍標記、`List<ChantTag>`。
- 曲名決定順序（為了不改變現有繁中使用者看到的內容）：
  - `zh_Hant`：音檔 metadata → 繁中目錄（＝現行行為）
  - `zh_Hans` / `en`：該語言目錄 → 音檔 metadata → 繁中目錄
- 分類標籤改為 `enum ChantTag`（穩定識別碼），篩選、預設排序一律以 enum 比對；
  顯示文字由 ARB 提供（`chantTag_<name>`，屬短字串 UI 標籤）。
- 曲目清單搜尋改為比對「目前語言的顯示文字」（曲名 + 標籤）。

### 4.3 畫面以外的文字（無 BuildContext）

以 `lookupAppLocalizations(locale)` 取得翻譯，`locale` 由 ViewModel 的已解析語言提供：

- `NotificationService`：每日提醒標題／內文、通知頻道名稱。語言變更時重新排程提醒，讓內文跟著換。
- `WidgetService`：`target_text`、`streak_text`、日期顯示，並**新增**推送 `widget_title`、`weekly_label`、
  `monthly_label` 等原本寫死在原生端的標籤。語言變更時立即同步小工具。
- `ChantAudioHandler`：系統通知欄／鎖定畫面的 MediaItem 標題、演出者、專輯改用內容目錄；
  語言變更時刷新目前曲目的 MediaItem。
- `AudioServiceConfig.androidNotificationChannelName`（於 `runApp` 前初始化）：
  以啟動時的已解析語言查表；頻道名稱建立後由系統保留，之後切換語言不保證更新（可接受）。
- ViewModel 本身維持不產生使用者可見文字（目前已符合）。

### 4.4 日期與數字

- 月曆標題、選中日期、小工具日期、星期列改用 `intl` 的 `DateFormat`（依語言），不手寫「年／月／日」。
- 每週起始維持週一（本週累計的定義不變），只換星期名稱的顯示。
- 數字維持阿拉伯數字；千分位格式（若有）用 `NumberFormat`。
- 數字輸入維持只允許 ASCII 數字（現有 `digitsOnly`），三個語言都不會產生其他數字系統。

### 4.5 原生層

- App 名稱多語系：
  - Android：`res/values/strings.xml`（英文預設）、`values-b+zh+Hant`、`values-b+zh+Hans`（以及 `values-zh-rTW`、`values-zh-rHK`、`values-zh-rCN` 相容舊版 Android），`android:label="@string/app_name"`。
  - iOS：`zh-Hant.lproj` / `zh-Hans.lproj` / `en.lproj` 的 `InfoPlist.strings`，`Info.plist` 加 `CFBundleLocalizations`。
- 桌面小工具：
  - 顯示用標籤全部改讀 Dart 推送的字串，原生端只保留繁中作為「尚未同步」時的後備。
  - Android 小工具在選擇清單中的名稱與說明走 `strings.xml`；iOS 小工具 `configurationDisplayName` / `description` 走小工具 extension 的 `Localizable.strings`。
- iOS 的 `.lproj` 需要登記進 Xcode 專案檔（`project.pbxproj` 的 knownRegions 與 variant group）。
  開發環境為 Windows，無法本機編譯 iOS，這部分需由使用者以 Codemagic / TestFlight 驗證。

## 6. 排版與英文長度

- 英文字串普遍較長，以下位置需在英文下檢查不溢位（窄螢幕 320dp 寬）：
  底部分頁列、自動計數小按鈕列（停止設定／減一／重置）、手動計數小按鈕列、月曆統計三欄、Drawer、設定頁。
- 必要時英文用較短的譯法（例如「減一」→「−1」、「重置」→「Reset」），而不是縮小字級。
- 不使用 `FittedBox` 硬塞長文字（現有計數數字的 `FittedBox` 保留）。

## 7. 測試與檢查

- `tools/check_arb_parity.sh`：`app_zh` / `app_zh_Hans` / `app_en` 三份 key 與 placeholder 完全一致。
- `resolveAppLocale` 單元測試：zh-TW、zh-HK、zh-MO、zh-Hant、zh-CN、zh-SG、zh-MY、zh-Hans、純 zh、en-US、ms-MY、ja-JP、多語言偏好清單的順序、手動設定覆蓋系統語言。
- 內容目錄測試：三個語言都涵蓋全部 31 首曲目與所有迴向文；繁中曲名決定順序與現行一致。
- 標籤篩選在三種語言下結果相同。
- 主要畫面在三種語言 × 窄螢幕下 widget test 無 overflow。
- 現有 widget test 改用共用測試 helper（包好 `localizationsDelegates` 並固定 `zh_Hant`），斷言文字不變。
- `flutter analyze`、`flutter test` 全過。

## 9. 留給實作者決定的部分

- ARB key 的具體命名（遵守第 4.1 節規則）。
- 內容目錄用 Dart const map 或 class 實作的細節。
- 測試 helper 的形式。
- 實作分階段的順序（建議：基礎建設與語言設定 → 畫面逐一遷移 → 內容目錄 → 非畫面服務 → 原生層），每階段結束都要測試全過。
